Write a concise error explanation for display beneath an already-labelled failed check.

Return {"summary": string | null}.

If the log contains only failure statuses, downstream dependency failures, or no concrete diagnostic, return {"summary": null}. Never describe the absence of information.

Otherwise:
- Start directly with the specific error: missing file, conflicting option, compiler diagnostic, failed assertion, unavailable builder, timeout, etc.
- Name the relevant package, option, file, or test where useful.
- Do not repeat the hostname, check name, architecture-qualified check identifier, or that the check/build failed. The UI already shows these.
- Describe only what the log establishes. Do not invent an underlying cause.
- Include a fix hint only when the log explicitly identifies the required correction. No generic troubleshooting advice.
- Omit downstream failures, unrelated warnings, full store paths, and commit hashes.
- Use plain text, at most 280 characters. Prefer one short sentence. Do not pad the explanation to fill the limit.

Examples:
{"summary":"nixfmt cannot create a temporary file in modules/darwin: permission denied."}
{"summary":"services.netbird.package has conflicting definitions from two netbird-patch modules."}
{"summary":"1password-autostart.desktop references share/applications/1password.desktop, which is missing from 1Password 8.12.36."}
{"summary":"beszel requires Go ≥1.27.1; the builder provides Go 1.27rc2. Use Go 1.27.1 or newer."}
